## Story Summary
As a CISO, I want source data quarantined by default and destroyed only after a separate, explicit authorization to ensure compliance with data retention policies.

## Vertical Scope
- **DB layer:** Cloud SQL to record `DISPOSAL_APPROVED` state, quarantine records, and destruction certificates.
- **Service layer:** Orchestrator executing SOURCE_QUARANTINED and DISPOSAL_APPROVED states.
- **API layer:** Endpoint to authorize multi-signature disposal and execute verifiable destruction.

## Acceptance Criteria
- Default action after migration is SOURCE_QUARANTINED (retention of source data).
- Disposal is blocked if validation exceptions, legal holds, or incomplete migrations remain unresolved.
- Requires a separate, multi-signature approval (DISPOSAL_APPROVED) before verifiable destruction.

## Test Outline
- [x] Happy path: Source disposal authorized via multi-signature and executed with SHA-256 certificate.
- [x] Edge case: Disposal blocked due to pending unresolved validation exceptions, legal holds, or incomplete migration.
- [x] Multi-signature quorum: Distinct authorized signatures required; duplicate signers rejected.
- [x] Dual storage & auditing: Both Cloud SQL relational records and Firestore collections updated with audit logs.
